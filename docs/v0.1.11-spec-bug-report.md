# v0.1.11 Spec: Bug Report of features implemented in v0.1.10: 

* Resolve Measuring Tool UI and data card visibility
* Resolve Measuring Tool State Persistence
* Implement Measuring Tool Clear Measurements Functionality

## 1. Context
In the current build, the measuring tool is exhibiting bugs related to UI rendering and state management, and lacks a dedicated method for users to clear existing measurements. This specification addresses the missing tooltip data card, fixes the improper clearing of measurements on tool deactivation, and introduces a specific, unambiguous "Clear Measurements" UI action.

## 2. Identified Issues & Feature Gaps
1. **Missing Tooltip Data Card:** The UI element (tooltip/data card) designed to show the **timespan** of the current measurement is not rendering. Only the blue line appears.
2. **Loss of Canvas State on Deactivation:** Untoggling the measuring tool improperly clears the existing measurement.
3. **Missing Clear Mechanism (Feature Gap):** There is currently no dedicated UI control to intentionally wipe active measurements from the canvas now that the untoggle behavior is being corrected.

## 3. Technical Requirements & Action Items

### 3.1. Fix Tooltip Data Card Rendering
* **Objective:** Ensure the data card displaying the measured timespan renders alongside the visual indicator (blue line).
* **Implementation Details:**
  * Verify that the timespan calculation logic is successfully passing its output to the tooltip component.
  * Check for conditional rendering bugs, missing CSS/z-index properties, or unhandled exceptions preventing the tooltip's display.

### 3.2. Fix Measurement State Persistence
* **Objective:** Keep the drawn measurement on the canvas after the measuring tool is untoggled.
* **Implementation Details:**
  * Decouple the visibility lifecycle of drawn measurements from the `isActive` state of the measuring tool.
  * Toggling the measuring tool to `false` must only disable event listeners for drawing *new* measurements; it must **not** trigger a clear function or remove existing measurement DOM nodes/canvas objects.

### 3.3. Implement "Clear Measurements" Control
* **Objective:** Provide a dedicated, explicit action to globally remove all measurements from the canvas.
* **Implementation Details:**
  * **UI Addition:** Render a new "Clear Measurements" icon strictly adjacent to the main ruler/measuring icon within the toolbar.
  * **Logic:** Bind an event listener to this new icon that immediately unmounts/destroys all measurement objects (e.g., SVG paths, canvas drawings, state arrays) from the canvas and resets the measurement state payload.
  * **Constraint:** Do not engineer complex features like confirmation dialogs, undo stacks, or single-item deletion. The requirement is a strict, global "clear all" execution upon click.

## 4. Acceptance Criteria
- [ ] **Measurement Creation:** User draws a measurement; the blue line appears **and** a tooltip data card showing the correct timespan is immediately visible.
- [ ] **State Persistence:** User toggles off the measuring tool; the blue line and measurement data **must remain visible** on the canvas. The toggle action solely controls the active drawing state.
- [ ] **Clear UI:** A new "Clear Measurements" icon is cleanly integrated and visible directly next to the ruler icon in the toolbar.
- [ ] **Clear Execution:** Clicking the "Clear Measurements" icon instantly and completely removes all measurement lines and associated tooltips from the canvas.
