# v0.1.10 - Technical Specification: Bug Fixes and Feature Enhancements

## 1. Context and Objectives
This document outlines a series of bug fixes and feature enhancements for the timeline/canvas application. The primary focus areas are resolving critical UX/UI issues with the newly introduced "Measure Tool," fixing initial application state logic, and expanding the `world_config` data model to support more granular user control over the canvas environment.

---

## 2. Bug Fixes

### 2.1 Measure Tool Interactions & Rendering
The Measure Tool is currently failing on interaction paradigms, visual feedback, and coordinate mapping. Implement the following corrections:

* [ ] **Toolbar Active State:** Modify the CSS/UI state of the Measure Tool icon on the toolbar to make its "toggled/selected" state explicitly obvious (e.g., distinct background color, active border, or inset shadow).
* [ ] **Canvas Cursor Override:** When the Measure Tool is active, force the canvas cursor to `crosshair`. 
    * *Constraint Note:* Ensure this overrides the default `grab`/`pointer` hand cursors. Verify the z-index (stacking context) of the canvas overlay so that object hover states do not preempt the crosshair when the tool is active.
* [ ] **Interaction Model Refactor (2-Click System):** Remove the current `mousedown` -> `mousemove` -> `mouseup` drag-to-draw logic. Implement a 2-click state machine:
    * **Click 1:** Registers the origin coordinate (X, Y) and begins the drawing state.
    * **Mousemove:** Renders a dynamic preview line strictly horizontally from the origin Y-coordinate to the current X-coordinate.
    * **Click 2:** Sets the termination coordinate, ends the drawing state, and commits the line to the canvas.
* [ ] **Dynamic Tooltip Card:** During the "Mousemove" phase (between Click 1 and Click 2), render a tooltip card tracking to the right of the cursor.
    * *Data:* It must display the calculated temporal distance (e.g., "52 years").
    * *Formatting:* Display this duration converted into *all currently visible time ruler units*, matching the display logic used in standard event cards.
* [ ] **Y-Coordinate Calculation Fix:** Fix the vertical offset bug. The horizontal line is currently rendering significantly below the cursor. 
    * *Action:* Recalculate the Y-coordinate on Click 1. Use `getBoundingClientRect()` relative to the canvas container to account for the heights of the navigation bar and visible time rulers, preventing the vertical offset drift.
* [ ] **Line Persistence:** Ensure the measurement line and its final associated tooltip data remain persistently rendered on the canvas after Click 2 is executed.

### 2.2 Application Initialization Logic
* [ ] **Empty Default State:** Stop using the hardcoded sample dataset on initial application load. The app must default to a completely blank canvas on startup.
    * *Verification:* Ensure no fallback mechanisms load sample data via `localStorage` or cached states. Sample data should exclusively be loaded via the "Import JSON" function or the explicit "Load Sample Dataset" UI trigger.

## 3. New Features

### 3.1 Data Editor Enhancements
* [ ] **"New World" Initialization:** Add a "New" action button to the Data Editor dialog. This should reset the current application state to an empty schema, allowing the user to populate a fresh world entirely via the internal lists and forms.
* [ ] **"World Settings" UI Tab:** Introduce a new tab within the Data Editor dialog titled "World Settings" to expose the new `world_config` JSON properties (detailed below).

### 3.2 Schema Updates: `world_config` Extensibility
Expand the root `world_config` object in the JSON schema to support the following configurable properties. Bind these to the new "World Settings" UI tab:
* [ ] `default_visible_timespan`: (Array/Tuple of Numbers) Overrides the default behavior of auto-scaling to the dataset's extents. Allows the data owner to specify the initial viewport boundaries.
* [ ] `default_mode`: (String) Enum of `'geographical' | 'biographical'`. Dictates the starting mode of the application (currently hardcoded to geographical).
(Note:  We will probably add more options to this section at a later date)
This will require a change to the data schema - this is OK. Just be sure to update the sampleData file accordingly.

### 3.3 UI/Typography Adjustments
* [ ] **Event Tooltip Typography:** Reduce the font size of the `date list` rendered inside the Event Tooltip Card. Update the CSS class so the date text perfectly matches the `font-size` and `line-height` of the standard event description text.
